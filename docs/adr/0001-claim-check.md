# 0001. 원본은 오브젝트 스토리지에, Kafka에는 참조만

## 상황

Parsoid HTML은 서울특별시 같은 문서가 1MB에 가깝다. Kafka 기본 메시지 한도(1MB)에 걸리고, 큰 메시지는 브로커 메모리와 복제 트래픽을 키운다. 한도를 올리는 방법도 있지만 컨슈머 fetch 크기까지 같이 맞춰야 하고, 결국 가장 큰 문서에 전체 설정이 끌려간다.

## 결정

- 수집기는 원본 HTML을 gzip으로 S3(`raw/<wiki>/<page_id>/<rev_id>.html.gz`)에 올리고 doc.events에는 URI만 넣는다.
- 중간 단계 메시지는 직렬화한 크기가 `KOWIKI_CLAIM_CHECK_BYTES`(기본 512KB)를 넘을 때만 `claims/`에 올리고 `claim-check` 헤더를 붙인다. 컨슈머는 헤더를 보고 알아서 풀어 읽는다.
- 원본 키에 rev_id가 들어 있어서 같은 판을 다시 받아도 같은 객체를 덮어쓸 뿐이다.

## 결과

- 토픽 설정은 기본값 그대로 둘 수 있다.
- S3가 느리거나 죽으면 파이프라인이 같이 멈춘다. S3 오류는 일시 오류로 보고 재시도한다.
- `claims/`는 토픽 보존 기간(7일)이 지나면 필요 없으므로 라이프사이클 규칙으로 지운다. 원본은 재색인에 다시 쓰므로 남긴다.
